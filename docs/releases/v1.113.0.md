# v1.113.0 — Opt-out module visibility (Control actually hides restricted modules)

**Nature:** minor (module gating now works the way an operator expects).

Directly addresses the feedback: *"each and every school can access every module
since the sidebar can not hide those that were restricted."*

## The problem

Module gating was **opt-in**: a module counted as enabled only if the school had
an explicit `is_enabled = 1` row. No school had those rows, so:

- the sidebar showed **everything** for everyone, and
- the module-mapped groups (Finance, Attendance, Academics) weren't even tagged,
  so toggling them in Control did nothing.

Tagging them under opt-in would have been worse — it would have **hidden** those
sections for every unconfigured school.

## The fix — opt-out (your chosen policy)

A module is now **enabled for every school by default**, and hidden only when
Control writes an explicit **disable**:

- `getEnabledModules` / `isModuleEnabled` / `getSchoolModuleStatus` flipped to
  "enabled unless an explicit `is_enabled = 0` row exists".
- The Finance, Attendance, and Academics top-level nav groups are now tagged with
  `requiredModules` (Tahfiz / Inventory / Payroll / Examinations / Analytics /
  Work-plans already were) — safe now that the default is enabled.
- `useEnabledModules` fails **open** (assumes all modules until the fetch
  resolves) so a slow/failed load never blanks the sidebar.

Net effect: in Control, toggle a module **off** for a school → it disappears from
that school's sidebar and the server gate rejects its routes. Leave it alone →
the school keeps it. No backfill, no live school loses anything.

## Server-side enforcement

`requireModule` already gates on `isModuleEnabled`, so flipping the semantics
makes every route that uses it enforce opt-out automatically (≈49 routes today,
Tahfiz/Inventory/etc.). Extending `requireModule` to the remaining
Finance/Academics/Attendance API routes is a mechanical follow-up — the sidebar
hiding + the gate mechanism are correct now.

## Under the hood

- New client-safe `src/lib/school-modules-codes.ts` (MODULE_CODES / ModuleCode /
  isModuleCode, no `@/lib/db`) so the sidebar hook can import the code list as a
  value without pulling the database layer into the browser bundle. Re-exported
  from `school-modules.ts`, so existing imports are unchanged.
