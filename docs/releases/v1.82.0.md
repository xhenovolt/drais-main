# DRAIS v1.82.0 — Attendance Digital Twin

**Attendance Intelligence Program · Phase 2** (baseline: `docs/audits/ATTENDANCE_ARCHITECTURE_AUDIT.md`)

## Release notes

Every punch is now a **fully traceable event** across its entire lifecycle:

> Fingerprint → Device → Device Time → Server Receive → Correction Engine → Identity Resolution → Attendance Record → Live Popup → Parent SMS → Audit

- **Event Explorer** — new page **/attendance/trace** (sidebar): search punches by name/PIN/date; each row carries identity/verdict/popup stage dots.
- **Trace Viewer** — click any event for a vertical timeline of all ten stages with ok/warn/fail/skip/info status, timestamps and plain-language detail. **The first red stage answers "where did it break?"** (unmatched → Identity fails and Verdict shows *skipped*; failed SMS shows the provider error; batch time corrections appear with their shift; store-and-forward uploads are explained rather than punished).
- **Inline from logs** — every row in /attendance/logs has a trace icon next to its time → jumps straight to that event's timeline.
- **Audit API** — `GET /api/attendance/trace?event_id=` (full trace) and `?q=&date=&limit=` (explorer list).

## Database changes

- One additive column: `attendance_raw_events.popup_at DATETIME NULL` (runtime best-effort ALTER). Stamped fire-and-forget by live-scan when a popup payload is served — never blocks the hot path. No other schema changes; the twin is a **read model** over evidence the pipeline already records (verbatim device time, ingest instant, resolution path, corrections, verdicts, outbox).

## API changes

- **Added** `GET /api/attendance/trace` (session-scoped). Additive only.

## Architecture notes

- `src/lib/attendance/trace.ts`: **pure** `composeStages()` + `traceSummary()` (the whole stage state machine is unit-tested with zero DB), plus thin loaders using the school's real UTC offset via `resolveTimePolicy`.
- Design choice: honesty over completeness — stages that cannot be known (punch predates popup tracking, no SMS policy) report `info`, never fake `ok`/`fail`.

## Risk analysis

- Read-only feature + one nullable-column stamp. The stamp is `.catch(() => {})`-guarded on the hot path.
- Explorer query bounded (limit ≤ 200), indexed by school/punch_at.

## Rollback plan

`git revert` the release commit. `popup_at` column can stay (nullable, unreferenced after revert) or be dropped manually — no data depends on it.
