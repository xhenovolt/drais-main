# DRAIS v1.88.0 — Device Intelligence

## Attendance Intelligence Program · Phase 7

Every biometric device becomes self-monitored, with a Device Reputation Score so maintenance is planned rather than reactive.

## Release notes
- **Device Intelligence** — new page /attendance/device-intelligence (sidebar, under Devices): a reputation score per device from four measured reliabilities:
  - **Clock** — RTC health from 30 days of device_clock_health (drift days, avg confidence)
  - **Upload** — how promptly punches reach the server (ingest lag) + days with no uploads
  - **Heartbeat** — how fresh/consistent the last-seen signal is
  - **Activity** — is it actually producing data (active days / 30)
- Each device shows the four sub-bars, an overall band (Reliable / Healthy / Needs attention / Maintenance required), a fleet average, and a concrete recommendation targeting the weakest reliability ("Replace the RTC coin-cell battery", "Check power and network", "Uploads unreliable — verify ADMS or pull over LAN"). Worst devices sort first.

## Architecture
- `src/lib/attendance/device-intelligence.ts` — **pure** `scoreDevice()` (10 unit tests) + a thin loader over existing tables (devices, device_clock_health, attendance_raw_events). No ML; explainable weighted reliabilities. Nothing written.
