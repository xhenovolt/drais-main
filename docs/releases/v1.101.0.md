# v1.101.0 — Historical Repair (Founder-Independence Phase E)

**Nature:** minor (a completely missing, founder-only capability is now built into DRAIS).

## What this closes

Phase E retires the **last script-only attendance workflow**. Until now, when a
*past* span of attendance read wrong — verdicts computed before an identity
correction, before a device clock was fixed, or before a duplicate-person merge
— the only remedy was a founder-run re-evaluation script over the database. A
normal school administrator could not do it.

Now they can, safely, from the UI.

## Re-evaluate a date range

Recovery Center gains a **"Historical repair — re-evaluate a past span"** panel:

- Pick a **From / To** date (and optionally scope to Staff or Learners).
- DRAIS rebuilds the attendance verdicts for every person who has punches in
  that window, using the **same `evaluateDay`** the live pipeline uses.

It is safe by construction:

- **Raw events are never touched.** Repair only recomputes the derived verdicts
  from the immutable punches (the source of truth).
- **Idempotent** — re-running over an already-correct span changes nothing.
- **Bounded** — a single run covers at most one term (92 days); larger spans are
  refused with guidance to repair in smaller windows.
- **No future dates.**
- **Audited** — every run writes an `ATTENDANCE_REEVALUATE_RANGE` audit row
  (range, scope, person-days touched, verdicts rebuilt).
- Requires `attendance.manage`.

## Under the hood

- `src/lib/attendance/historical-repair.ts`
  - `planRange(from, to)` — **pure**, unit-tested: YYYY-MM-DD validation,
    reversed-range tolerance, 92-day cap, future rejection.
  - `reevaluateRange({ schoolId, from, to, role?, personId? })` — enumerates the
    distinct (person, role, local-date) with punches in the UTC window and
    re-evaluates each day.
- `src/app/api/attendance/historical-repair/route.ts` — `POST reevaluate_range`.
- Recovery Center panel (`src/app/attendance/recovery/page.tsx`).
- 7 unit tests, all passing (`historical-repair.test.mjs`).

## Founder-independence status

With Phase E shipped, the corrective-data workflows an administrator can now run
without the founder, SQL, or scripts:

| Workflow | Phase | Route |
|---|---|---|
| Correct a misattributed identity + **undo** | A | Attendance Logs |
| Daily digest of attention items | D | Health Center |
| Roster hygiene / enrollment-mismatch fix | C | Profiles |
| Merge duplicate people | B | Identity Intelligence |
| **Re-evaluate a past date range** | **E** | **Recovery Center** |

Remaining audit phases: **F** (EN+AR localization & accessibility of the
intelligence pages) and **G** (route robustness / `withRoute` wrapper).
