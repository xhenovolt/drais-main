# v1.120.0 — Console security Phase 9: impersonation kill-switch

**Nature:** minor (security — E-3). Second increment of the Security wave.

## What this closes

Impersonation could be *started* and audited, but once running there was no way
to **see** which schools were being impersonated or to **revoke** access — a
leaked or forgotten 2-hour session just ran to expiry.

## Now

- **Active-impersonation view** — the Control dashboard shows every live
  impersonation across the platform (operator → school, operating-as user, time
  left, source IP), auto-refreshing every 30s. The panel only appears when
  something is live.
- **Per-session revoke** — end any single impersonation immediately.
- **Kill switch** — "Revoke all" ends every live impersonation at once.

Revoking flips the tenant session inactive on the spot (the next request is
rejected), and every action is audited (`impersonation_revoked` /
`impersonation_revoked_all`).

## API / code

- `src/lib/control/impersonation.ts` — `listActiveImpersonations`,
  `revokeImpersonation(sessionId)`, `revokeAllImpersonations()`.
- `GET/POST /api/control-center/impersonations` — list + revoke one / all
  (revoke requires `canManage`).
- Dashboard `ImpersonationsPanel` with per-row + revoke-all controls.

No new cron; no schema change (reuses the existing `impersonated_by_control_user`
flag on `sessions`).
