# DRAIS v1.86.0 — Automatic Attendance Recovery

## Attendance Intelligence Program · Phase 5

When attendance stops flowing, DRAIS now notices and offers the fix — instead of the founder discovering a gap days later.

## Release notes
- **Recovery Center** — new page /attendance/recovery (sidebar): per-device gap detection comparing today's ingest against the learned daily volume + last-punch age, each with a plain-language reason and a recommended recovery method:
  - **LAN pull** → routes to Device Control (the existing pull+stage+commit wizard) to backfill offline-stored punches
  - **Resume acquisition** → a pull is staged but never committed
  - **Retry queue** → drains the notification outbox in place (the one safe self-service action)
  - **Check device** → no LAN route; inspect on site
- **Inline gap banner** on attendance/logs (?banner=1 poll) — the gap finds the operator where they work.
- School-wide recoverables surfaced too: uncommitted acquisitions, stuck SMS queue.

## Architecture
- `src/lib/attendance/recovery.ts` — **pure** `recommendMethod()` (9 unit tests, no DB) + `detectGaps()` loader. Reuses existing machinery entirely: learned baselines (Time Intelligence), the acquisition/commit wizard (Device Control), and the outbox drainer. Nothing is auto-applied — recovery stays operator-confirmed; this layer only diagnoses and routes.

## Database changes
None — reads existing tables (devices, attendance_raw_events, attendance_time_baselines, attendance_acquisitions, notification_outbox).

## Validation
Live on JIPRA: detected the 3 uncommitted device pulls and routed them to "resume acquisition" — the exact debt the Health Center had flagged.

## Tests
163 pass (9 new). Build clean.

## Rollback
`git revert`; the retry-queue action reuses the existing drainer, no new state.
