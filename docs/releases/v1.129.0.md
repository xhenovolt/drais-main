# v1.129.0 — Automation wave Phase 18: in-DB job runner (breaks the single-cron ceiling)

**Nature:** minor (E-14). The foundational automation primitive for the
resilience wave — **without ever adding a cron.**

## The problem

Vercel Hobby allows exactly ONE cron, and DRAIS already uses it — everything
periodic (attendance sweep, digest, dunning) had to piggyback that one daily
fire, with no retry if a step failed.

## The fix — a job queue on the one cron

Periodic / retryable work is now a **`platform_jobs`** row, dispatched by the
**existing** cron (and any request-driven tick):

- `enqueueJob({ type, payload, runAfterSec?, dedupKey? })` — enqueue work;
  `dedupKey` makes it idempotent (a repeat while pending is a no-op).
- `runDueJobs()` — **atomically claims** due jobs via a unique lock token (so
  overlapping ticks never double-run), runs each registered handler, and on
  failure **retries with exponential backoff** (60s → … → 1h cap) up to
  `max_attempts`, then marks it failed. A stale `running` job (crashed mid-flight)
  is reclaimed after 10 minutes.
- Handlers register via `registerJobHandler(type, fn)`; the core set lives in
  `job-handlers.ts`.

**No new cron is ever created** — the single existing cron calls
`registerCoreHandlers()` → `enqueueJob('dunning', …)` → `runDueJobs()`.

## First adopter: dunning

Billing dunning (Phase 14) now runs **as a job**, so a failed run **retries**
instead of being lost for the day. Future phases (health snapshots,
reconciliation retries, backup checks) just register a handler + enqueue.

## Observability

- `GET /api/control-center/jobs` — recent jobs (status / attempts / last error);
  `POST { }` drains due jobs now (super-admin — a manual, request-driven tick).
- **System Health → Background jobs** panel: live status chips + a **Run due
  now** button.

## Code + tests

- `src/lib/control/job-runner.ts` — schema (`platform_jobs`), enqueue/claim/
  dispatch, and the **pure** `computeBackoffSeconds` + `isDue` (5 unit tests).
- `job-handlers.ts` (dunning), cron wiring, jobs API + panel. 88/88 control
  tests green. Additive schema; **no new cron.**
