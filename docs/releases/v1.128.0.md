# v1.128.0 — Selective (per-person) attendance time correction

**Nature:** minor. Fixes a real data-integrity gap: when only *some* people's
punch times are wrong, you can now correct just those — not the whole device
batch.

## The problem

Time correction only worked on the **whole device batch** for a day. But often
just a subset of punches are wrong — e.g. yesterday a handful of staff read as
**4:26 AM / 2:16 AM / 1:25 AM** (an AM/PM mix-up) while everyone else was fine.
Shifting the whole batch would have corrupted the correct ones.

## Now — fix only the selected punches

On **Attendance → Logs**, select the specific rows that are wrong (the existing
row checkboxes), then use the new **Correct time** actions in the selection bar:

- **+12h (AM→PM)** — the common fix for times read as AM that were really PM.
- **−12h (PM→AM)**.
- **Shift…** — any custom number of hours (e.g. `5`, `-3`, `1.5`).

Only the **selected** punches move; everyone else is untouched. Original device
times (`device_reported_time`) are preserved, the affected day-verdicts are
recomputed (both the old and the shifted date), and the correction is
**undoable from Time Health** like any other (it's recorded as a `selective`
correction with per-punch originals).

## Code + tests

- `time-intelligence/engine.ts` — `correctPunches(schoolId, ids[], shiftMinutes)`:
  snapshots originals → shifts the specific `attendance_raw_events` by id →
  reuses `reevaluateAffected` (re-evaluates pre- and post-shift days) → recorded
  in `attendance_time_corrections` (source `selective`, undoable).
- `POST /api/attendance/time-health` gains `correct_selected { ids, shift_minutes }`
  (≤500 punches, sane shift, permission-gated).
- Attendance Logs selection bar: +12h / −12h / Shift… actions. 20/20 time tests
  still green.

No new cron; no schema change (reuses the existing corrections table + undo).
