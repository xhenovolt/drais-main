# v1.125.0 — Money wave Phase 14: dunning + tenant communications

**Nature:** minor (E-8 + E-11). Schools are no longer suspended silently.

## What this adds

The platform now **tells schools** about their subscription instead of just
cutting them off:

- **Expiry warnings** — an in-app notice to each school's admins when the
  subscription is **7 days** out and again the **day before**.
- **Suspension notice** — when it lapses, admins are told access is suspended and
  how to restore it.
- **Renewal / payment receipt** — when a payment reconciles an invoice in full,
  admins get "payment received — active until {date}".

Notices go to each school's admins/head-teacher/director, in-app (cost-free,
always available), deduped **once per stage per school per day**.

## How it runs (no new cron)

The dunning sweep piggybacks the **existing** daily cron
(`/api/result-deadlines`), right after the attendance digest — honouring the
one-cron Hobby limit. It only scans schools within 7 days of expiry (or past it),
so it's cheap.

## Code + tests

- `src/lib/control/dunning.ts` — **pure** `dunningStage(days)` (4 unit tests) +
  `runDunningSweep` + `notifyTenantBilling` (reuses `NotificationService`, admin
  resolution mirrors the attendance digest).
- `billing.ts` `recordPayment` now fires a `billing_renewed` notice to the school
  on full payment.

No schema change; no new cron.
