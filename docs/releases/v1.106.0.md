# v1.106.0 — Device tenant isolation + ownership moved to platform (Control Center P1)

**Nature:** minor (closes a live cross-tenant data leak; relocates a capability).
Also carries an urgent **build/deploy fix**.

## 🔴 The leak this closes (P0)

Every school could see **every** school's devices. `GET /api/attendance/zk/devices`
— the API the `/attendance/devices` page loads — resolved the session but never
filtered by it (`FROM devices d WHERE d.deleted_at IS NULL`, params `[]`), and
its PUT/DELETE were equally unscoped, so a school could also **rename or delete
another school's hardware** by id.

Fixed — every device query is now bound to the caller's school:

- **GET** list, the discovery fallback (`zk_attendance_logs`), and the debug
  heartbeat query all now filter `school_id = session.schoolId`.
- **PUT** / **DELETE** verify **and** mutate only `WHERE id = ? AND school_id = ?`.

### Retired orphaned endpoints (410)

Unauthenticated / param-injectable device endpoints with no callers, removed:

- `GET /api/devices/list` — unauth, unscoped device dump.
- `GET /api/devices/summary` — unauth, unscoped counts.
- `GET /api/attendance/zk/live` — read `school_id` from a query param (default 1),
  a cross-tenant read. The live UI uses session-scoped `live-identity` / `live-scan`.

## Device ownership is now a PLATFORM operation, not a tenant one

A school being able to release/acquire/transfer hardware means one tenant can
affect another's data — wrong by design. Ownership ceremonies
(`/api/admin/devices/[sn]/{release,acquire,decommission}`) are now **super-admin
(Xhenvolt Control) only**; the school-facing transfer buttons render only for
super-admins. The server enforces the rule regardless of the UI. (Full Control
Center device-management UI is roadmap P2.)

## Regression guard

`device-isolation.test.mjs` (9 tests) statically asserts the invariants so a
future edit that drops a `school_id` filter, un-retires an orphan, or un-gates a
transfer **fails CI**: list/fallback/PUT/DELETE are school-scoped, the three
orphans return 410 with no DB access, and the three transfer routes reject
non-super-admins.

## 🛠 Build/deploy fix (urgent)

The Vercel build was OOM-**SIGKILL**'d — native webpack/SWC memory on an 8 GB
container, which the JS heap cap cannot bound. Enabled
`experimental.webpackBuildWorker` so webpack compiles in a dedicated worker whose
memory is released between the client/server compiles, bounding the peak.
(A separate fix this cycle made `/api/reminders` build lazily — v1.105.1.)

## Not changed / verified safe

- Attendance **records/logs** were already correctly school-scoped — unaffected.
- The claim/transfer flow is by serial number, so scoping the list did **not**
  break onboarding.
