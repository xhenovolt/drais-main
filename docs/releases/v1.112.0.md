# v1.112.0 — School lifecycle: archive / delete / restore (Roadmap P6)

**Nature:** minor (school lifecycle management from the Control Center).

Continues the operator-feedback work: schools can now be archived, soft-deleted,
and restored from Control — and those states are actually **enforced** in the
school app.

## What you can do now

On `/control/schools/[id]` → **Lifecycle** panel:

- **Archive** — pause a school (kept recoverable, data untouched, marked inactive).
- **Delete** — soft-delete: the school disappears from the platform but **all
  data is preserved** and it can be restored later. Nothing is ever hard-deleted.
- **Restore / Un-archive** — bring an archived or deleted school back to active.

A reason can be attached to archive/delete; every action is audited
(`school_archived` / `school_deleted` / `school_restored`).

The schools list gets a **Show deleted** toggle, and status badges now
distinguish active / suspended / **archived** / **deleted** (colour-coded) on
both the list and detail views. A deleted school is still viewable (so it can be
restored) but visually dimmed.

## Enforcement (important)

Previously the session gate only blocked **suspended** schools; a soft-deleted or
archived school could still be operated because the school→session join silently
dropped deleted rows (status read as NULL). Now `getSessionSchoolId`:

- blocks a session whose `school_id` no longer resolves to a live row
  (**soft-deleted** → `SCHOOL_DELETED`), and
- blocks **archived** schools alongside suspended ones.

So Archive and Delete take effect immediately for the tenant, not just visually
in Control. Restore lifts the block.

## API

- `POST /api/control-center/schools/[id]` gains `archive` / `soft_delete` /
  `restore` actions (super-admin, audited).
- The detail `GET` no longer filters out deleted schools (so they can be viewed
  and restored); the list `GET` accepts `?include_deleted=1`.
