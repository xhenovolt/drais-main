# DRAIS v1.89.0 — Identity Intelligence

## Attendance Intelligence Program · Phase 8

Rigid device→person mappings become a graded, self-diagnosing surface with proposed (never automatic) fixes.

## Release notes
- **Identity Intelligence** — new page /attendance/identity-intelligence (sidebar, under Devices & Biometrics): an identity-health score plus a prioritised issue list:
  - **duplicate** — one person mapped to several device PINs → propose MERGE, keeping the most recently active PIN and naming which to unmap
  - **unknown** — a PIN producing punches with no confirmed person → propose MAP (with the device's own name as the suggestion when available)
  - **stale** — an enrollment the device hasn't recorded in 30+ days → REVIEW/revoke
- Nothing changes here: every action routes to the existing Identity Matching flow where a human confirms. Duplicates carry the heaviest penalty (they silently double-count attendance).

## Architecture
- `src/lib/attendance/identity-intelligence.ts` — **pure** `classifyIssues()`, `chooseKeeper()`, `scoreIdentityHealth()` (11 unit tests). The loader reads existing tables (biometric_enrollments, attendance_raw_events, device_user_directory). No ML, no schema changes, no auto-mutation.

## Validation
Live on JIPRA: surfaced 8 duplicate staff mappings + 103 unknown PINs, recommending e.g. "Keep PIN 114 (most recently active) and unmap 5" — the long-standing duplicate device accounts, now actionable.
