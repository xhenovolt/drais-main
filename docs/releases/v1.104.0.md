# v1.104.0 — Route robustness: withRoute wrapper (Founder-Independence Phase G)

**Nature:** minor (a new, reusable robustness layer added; founder-independence
routes adopt it).

## What this closes

The final founder-independence phase, and the on-ramp to the route-hardening
plan. The route audit flagged **R-8: 112 API routes had no try/catch** — an
unhandled throw there crashes the request instead of returning a clean error.
On top of that, every route hand-rolled the same four-step preamble: resolve the
session → 401 → `requirePermission` → wrap the body in try/catch. Copy-pasted
boilerplate is where robustness quietly rots.

This ships **`withRoute`** — one wrapper that gives a route, uniformly and for
free:

- **authentication** — the session is resolved once; missing → `401` (unless the
  route opts out with `auth:false`);
- **authorization** — an optional `permission` enforced; missing → `403`;
- **robustness** — the handler runs inside try/catch, so an unexpected throw
  becomes a clean JSON **500** (logged) instead of a crashed lambda;
- **a consistent error envelope** — always `{ error: string }` with the right
  status (the exact shape every DRAIS client already reads), honouring an
  `err.statusCode` when a handler throws a typed error (a 400 validation, a 403
  permission). Internal 500 messages are hidden in production.

Handlers shrink to just the logic and may return a plain object (→ `200` JSON)
or their own `NextResponse`:

```ts
export const POST = withRoute({ permission: 'attendance.manage' },
  async ({ session, body }) => {
    const b = await body();                 // memoised, never throws
    if (!valid(b)) throw badRequest('…');   // → 400 { error: '…' }
    return { success: true, ... };          // → 200 JSON
  });
```

## Adopted this release

The founder-independence routes built across Phases B–E now run on `withRoute`,
losing ~15 lines of preamble each and gaining uniform error handling:

- `POST /api/attendance/historical-repair` (Phase E)
- `GET/POST /api/attendance/person-merge` (Phase B)
- `GET/POST /api/attendance/roster-hygiene` (Phase C)
- `GET/POST /api/attendance/digest` (Phase D)

Response shapes and status codes are unchanged — the UIs that read `j.error` /
`j.success` keep working exactly as before.

## Under the hood

- `src/lib/api/with-route.ts` — the wrapper (auth, permission, body memoisation,
  param resolution incl. Next 15 promised params, plain-object → JSON).
- `src/lib/api/resolve-error.ts` — the **pure** error→HTTP mapping, split out so
  it is testable without pulling in `next/server`.
- `src/lib/api/__tests__/resolve-error.test.mjs` — **8 unit tests, all passing**
  (4xx passthrough, `status`/`statusCode`, prod message hiding, 5xx-throw still
  hidden, null/odd throw safety).

Complements the existing `withErrorHandler` (catch-only); `withRoute` is the
fuller wrapper for routes that also need auth + permission.

## Founder-independence program — complete

Phases **A–G are all shipped**. An ordinary school administrator can now, without
the founder, SQL, scripts, or AI: correct & undo identity attributions, receive a
daily attention digest, clean the roster, merge duplicate people, re-evaluate any
past date range, and do all of it in Arabic or English — over API routes that
fail safe. Remaining work is the broader route-hardening rollout (migrating the
other ~110 routes onto `withRoute`), tracked separately.
