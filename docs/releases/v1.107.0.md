# v1.107.0 — Control Center device management (Roadmap P2)

**Nature:** minor (a whole missing subsystem added to the platform layer).

## What this adds

P1 made device ownership a **platform** operation and removed it from schools.
P2 is where that ownership now *lives* — a real device-management surface inside
the Control Center, so Xhenvolt administers hardware without SQL or impersonation.

### `/control/devices` — platform device inventory

Every device across every school in one place, with owner school, status, online
state, search (SN / name / location) and status filter. Unassigned devices are
surfaced (and counted) so the NULL-school bleed is now a **worklist**, not a leak.

Per-device platform actions (super-admin, audited):

- **Assign / Reassign** — claim an unclaimed device to a school (fixes the
  NULL-school problem), or reassign a released one. A never-owned device is
  claimed directly; a released device goes through the vetted acquire ceremony.
- **Release** — hand a device back (runs the real `transfer-service` release, so
  enrollment archival + audit are identical to the old flow).
- **Suspend / Activate** — take a device out of / back into service.
- **Retire** — decommission (terminal) via the vetted ceremony.
- **Ownership timeline** — the full `device_transfers` history per device
  (assign / release / acquire / retire), with school names and impact counts.

## Durability fix (important)

The ZK heartbeat upsert used to force `status='active'` + `deleted_at=NULL` on
**every** ping ("resurrection") — so a platform Suspend/Retire would be silently
undone on the device's next heartbeat. The upsert now respects a deliberate
platform state:

```sql
status     = IF(status IN ('suspended','retired'), status, 'active'),
deleted_at = IF(status IN ('suspended','retired'), deleted_at, NULL)
```

So Suspend and Retire are now **durable** against a live, still-pinging device.

## API + code

- `src/lib/control/devices.ts` — `listPlatformDevices`, `runDeviceAction`
  (assign/release/suspend/activate/retire), `deviceTimeline`, and the **pure**
  `validateDeviceAction` (4 unit tests). Reuses `transfer-service` for the
  release/acquire/decommission ceremonies (fromSuperAdmin), so archival + audit
  are unchanged.
- `GET/POST /api/control-center/devices` (list + action; POST needs `canManage`)
  and `GET /api/control-center/devices/[sn]` (timeline).
- `/control/devices` page + a **Devices** nav entry in the Control Center shell.
- Every mutation writes `control_audit_logs` (device_assigned / released /
  suspended / activated / retired) with the operator + IP.
