# DRAIS v1.173.87 — Sentinel, Import Redesign, Stability Hardening, WhatsApp

30 commits since v1.173.64. Four major bodies of work: a self-healing
infrastructure monitor (Sentinel) built from scratch and then made honest
about what its own score means; a full rebuild of the Excel/CSV student and
fee import pipeline; a wide stability/reliability/security pass that found
and closed real, live production bugs; and a first-class WhatsApp Business
messaging channel alongside SMS.

## DRAIS Sentinel — self-healing infrastructure monitor (new)

A background monitor that watches DRAIS's own health instead of waiting for
a founder to notice something's wrong.

- Observers for background jobs, notifications, security, fleet health,
  academics, API health, import health, and static tenant-isolation
  analysis, feeding an incident table with severity, dedup, and escalation
  (10,000 identical failures collapse to one incident, not 10,000).
- A "Full System Diagnosis" engine scoring DRAIS 0–100 across weighted
  dimensions (tenant isolation, CI safety, test coverage, unbounded
  queries, background job scheduling, live attendance reliability, job
  liveness) — redesigned mid-cycle after the headline number was found to
  be flattening two different questions ("is this route protected" vs
  "does it use one specific wrapper") into one misleading score. Now
  reports both, weighted by how directly each one predicts real risk.
- Per-school API-health breakdown, a nav entry, and results-import failure
  detection (bulk + manual submission gaps) folded in as separate
  observer work.

## Excel/CSV import — full redesign (students, fees)

Replaced 4–5 inconsistent, partially-overlapping import code paths with
one pipeline, shipped in phases alongside the legacy importer (never
retired — opt-in via `/students/import-v2`, `/finance/import-v2`):

- **Workbook intelligence**: real header-row detection (not "always row
  0"), sheet-name context extraction (`"S.2 Blue"` → class + stream),
  purpose-guessing per sheet (students vs fees vs results), so a workbook
  with sheet-per-class and no class column, or mixed fees+students sheets,
  is understood correctly.
- **Flexibility fixes driven by real usage**: a workbook with one combined
  "Student Name" column (no separate First/Last) now imports correctly
  instead of failing outright; `admission_no` is no longer required —
  absent, DRAIS auto-generates a stable number instead of rejecting the
  row.
- **Fees pipeline**: consolidates four separate fee-writing code paths
  into one, routed through the already-proven-atomic `recordPayment()`
  rather than new raw SQL; admission-number-only identity matching
  (deliberately no fuzzy name matching for money).
- **A critical bug caught by live testing, not review**: the v2 student
  importer's actual database-write path referenced columns that don't
  exist on `students` (name/gender live on `people`) and tried to write
  directly to a `STORED GENERATED` column — broken since Phase B, and
  invisible to every prior test because they all used dry-run or
  pure-function checks. Found only when actually committing a real import
  against the real database. Fixed and re-verified live.
- Sentinel import-health observer (failure-rate anomalies, repeated
  failures, unusually large runs), performance-tested to 10k rows
  (~9k rows/sec), re-import idempotency and partial-failure recovery
  proven against a stateful fake DB.

## Report-card correctness

- **Nursery report cards showed grade E regardless of real performance** —
  two separate bugs in two different code paths (the report-builder never
  used a grouped subject's `regularScore`, and — after that first fix
  didn't resolve what users were actually seeing — the real rendering
  path's `DRCEResultRow` transform read a `score` field that doesn't exist
  on those rows at all). Both fixed and verified against real production
  data: a learner with real scores in the high 90s now correctly shows
  division A, not E.
- DRCE grouped-results table: show/hide band label toggle, core-subject-
  first ordering default.
- Division-based overall comment rules seeded for Albayan; class
  teacher/DOS/headteacher comments now reflect actual performance instead
  of static text.

## Security

- **7 real cross-tenant data leaks found and closed**, discovered while
  auditing Sentinel's own tenant-isolation scanner rather than waiting for
  a report: full cross-school device-log visibility (names included, not
  just metadata) via two routes; two device-command endpoints that
  accepted a foreign school's device through an unguarded `||` fallback;
  two command-status endpoints with no ownership check; and a relay-status
  endpoint with **no authentication at all** on its browser-facing paths.
- **~90 more `deleted_at` filter gaps closed** in a codebase-wide sweep
  (Phase 2/3 of the stability roadmap), which also surfaced and fixed:
  unauthenticated write endpoints, a hardcoded demo user ID in an audit
  log, and several routes reading columns that don't exist on `students`
  (crashing on every call — two of them live and reachable from the UI).
- Sentinel's tenant-isolation scanner rewritten to distinguish "verified
  but manual" protection from "the one canonical wrapper" — the prior
  version scored the codebase as 2% protected when the real number,
  individually verified file by file, is 100% (191/191) accounted for.
- Audit logging extended to 9 previously-silent config-change routes
  (school config, branding, attendance settings, device config, roles,
  permission sync).
- A real Sentinel CI gate added — no workflow previously blocked a broken
  build or failing test from merging.

## Reliability — three background jobs found silently dead

- **Billing dunning and platform-health snapshots stopped running for two
  weeks**, discovered by checking Sentinel's own incident log rather than
  trusting it. Root cause: the daily job dispatcher was a fire-and-forget
  promise racing the HTTP response, which the serverless platform is free
  to kill mid-flight — and one failing step silently skipped every step
  after it. Fixed with `after()` (the supported mechanism for exactly
  this) and independent error handling per job, so one system's failure
  can no longer starve the others.
- **The device-offline sweep had never run in production at all** —
  fully built, but never wired to any trigger. A real device sat
  incorrectly marked "online" for 7+ days as a direct result. Fixed and
  verified live: the sweep now runs on a daily floor plus opportunistically
  on every device heartbeat, and correctly flipped the affected device to
  offline the moment it ran.
- Sentinel's own self-check heartbeat had a bug that made it permanently
  report "unmonitored" regardless of actual health — fixed and confirmed.
- Three deliberately-unpaginated list endpoints (`students/list`,
  `/admitted`, `/enrolled`) given a 10,000-row safety ceiling — no
  behavior change for any real school today, but no longer truly
  unbounded at extreme scale.
- A cross-platform bug in the CI test suite itself (Windows path/shell
  quoting) found and fixed while adding the CI gate.

**Net result of the Sentinel/security/reliability work**: DRAIS's own
diagnosis score moved from 47/100 to 81/100 — not by changing the scoring
formula in isolation, but from real, verified fixes plus a scoring
methodology that no longer conflates a maturity signal with a live safety
one.

## WhatsApp Business messaging (new, via Infobip)

A first-class WhatsApp channel alongside SMS, in both the school admin UI
and the platform Control Center — provider-abstracted so a second WhatsApp
provider can be added later without a rewrite.

- School-level settings (enable, business sender, provider, optional
  per-school Infobip credential override), a WhatsApp option in the
  automation-rules channel picker, and a test-send button.
- Delivery-status webhook (queued → sent → delivered → read → failed),
  idempotent and rank-ordered so a duplicate or out-of-order callback can
  never regress an already-more-advanced status.
- Control Center cross-school communications overview — delivery counts
  and rates by channel and by school, reusing the existing dispatch-log
  table (no new tables for this).
- Verified live against the real Infobip account (an authenticated
  connectivity check, not a real message send — no WhatsApp Business
  sender number is configured yet). **Known gap, not yet resolved**: real
  outbound notifications need a Meta-approved message template outside
  the 24-hour reply window; this ships the free-text endpoint only.
- First-ever test suite for the communications module (33 tests) —
  none existed before, for any channel.
