# v1.121.0 — Console security Phase 10: optional 2FA (TOTP)

**Nature:** minor (security — E-2). Third increment of the Security wave.
**2FA is strictly optional — never forced.**

## What this adds

Per-operator two-factor authentication for the Control Center, opt-in:

- **Enable** from Operators → *Two-factor authentication (your account)*: DRAIS
  generates a TOTP secret + `otpauth://` URI; add it to any authenticator app
  (Google Authenticator, Authy, 1Password…), enter the 6-digit code to confirm.
- **Recovery codes** — 8 one-time codes are shown once on enable (only their
  hashes are stored); any one gets you in if you lose your device.
- **Login** — when an operator has 2FA on, login asks for the code after the
  password (a `needs_2fa` step on the login screen). A recovery code also works
  and is consumed on use.
- **Disable** requires a current code (or recovery), so a hijacked session can't
  silently turn it off.

Operators without 2FA are completely unaffected — there is no global requirement.
Enable / disable / recovery-use are audited (`twofactor_enabled` /
`twofactor_disabled` / `twofactor_recovery_used`).

## Implementation

- `src/lib/control/totp.ts` — RFC-6238 TOTP on `node:crypto` (**no new
  dependency**): base32, `totpCode`, `verifyTotp` (±1 step skew), `otpauthUrl`,
  recovery-code gen + forgiving hash. **All pure, 9 unit tests.**
- `auth.ts` — `beginTotpEnrollment` / `confirmTotpEnrollment` / `disableTotp` /
  `getTotpStatus`; `loginControl` enforces the second factor only when enabled.
- `control_users` gains `totp_secret` / `totp_enabled` / `totp_recovery`
  (additive runtime migration).
- `GET/POST/PUT/DELETE /api/control-center/2fa` (self-service); login route
  surfaces `needs_2fa`; login + operators UIs updated.

No new cron.
