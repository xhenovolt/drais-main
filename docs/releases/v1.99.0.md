# DRAIS v1.99.0 — Bulk Roster Hygiene (Founder-Independence Phase C)

Closes gap FD-3: cleaning a bloated/mislabelled roster used to require SQL/scripts, which made the attendance intelligence "true but noisy" and over-counted absence. Now it's a safe, reversible, audited admin action — no founder.

## What shipped (on /attendance/profiles)
- **Bulk deactivate never-present people.** The "Roster review" list (people who never once checked in — likely former or unenrolled) now has checkboxes + Select-all + **Mark N inactive** / **Reactivate**. Deactivation sets `status='inactive'` (never deletes), so it's fully reversible and removes them from active rosters and absence expectations — the intelligence immediately reflects real people.
- **Enrollment mismatch fixer.** DRAIS detects learners who are actively enrolled but marked inactive (their attendance silently isn't tracked) and offers a one-click **Activate N learners** — turning the "0 active students despite live enrollments" situation into a fix an admin does themselves.
- Both are confirmed, reversible and audited (logAudit).

## Architecture
- `src/lib/attendance/roster-hygiene.ts` — **pure** `validateHygieneAction()` (8 tests: id filtering, batch cap, role/action guards) + `setPeopleStatus` / `fixEnrollmentMismatch` / `hygieneCounts`.
- `/api/attendance/roster-hygiene` (GET counts; POST deactivate/reactivate/fix_enrollment_mismatch). Reuses the existing `status`/soft-delete model — nothing deleted.
