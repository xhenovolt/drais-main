# v1.122.0 — Console security Phase 13: control RBAC (least-privilege operators)

**Nature:** minor (security — E-4). **Final increment of the Security wave.**

## What this changes

The Control Center was binary: only `XHENVOLT_SUPER_ADMIN` could do anything;
`OPERATOR` and `VIEWER` existed but were undifferentiated. Now there's a real
permission catalog so support/ops helpers can be delegated **least-privilege**:

| Role | Can do |
|---|---|
| **Super-admin** | everything (platform owner) |
| **Operator** | schools (status/modules/subscription/plan/archive/soft-delete/restore), devices, impersonation — but **not** the plan catalog, operators, or permanent delete |
| **Viewer** | read-only (view schools/devices/health/audit/plans) |

## Enforcement

- Pure `controlCan(role, permission)` (7 permissions) — **4 unit tests**.
- Every mutating control route now gates on a **specific** permission instead of
  the blanket super-admin check:
  - school changes → `schools.manage`; **permanent delete → `schools.hard_delete`**
    (super-admin only)
  - devices → `devices.manage`
  - plan catalog create/edit/delete → `plans.catalog` (super-admin only)
  - impersonate + revoke → `impersonate`
  - create/manage operators → `operators.manage` (super-admin only)
- Reads stay open to any authenticated control session (viewer included).
- Operators can be created with any of the three roles from the Operators page.

Net effect: you can now hand a colleague an **Operator** login to run schools and
devices day-to-day, or a **Viewer** login for read-only oversight, without giving
away God-mode.

## Code

- `src/lib/control/permissions.ts` — catalog + `controlCan` / `permissionsFor`.
- Six control-center routes migrated off `canManage` to `controlCan(…, code)`.

No new cron; no schema change.
