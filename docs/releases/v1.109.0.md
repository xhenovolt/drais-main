# v1.109.0 — Platform Health Center (Roadmap P4)

**Nature:** minor (a proactive cross-school monitoring subsystem).

## What this closes

Defect #9: the founder discovered broken schools by accident. The Control
Center's system-health page only showed platform *aggregates* (total devices
online, total SMS failed) — never *which school* had a problem.

Now the platform **scans every school** and reports the ones that need attention,
worst-first, each linking straight to its operations view.

## Monitors (per school, no N+1)

Each is a single `GROUP BY school_id` query, merged into a per-school issue
register:

| Monitor | Severity | Fires when |
|---|---|---|
| Licence expired | critical | `subscription_end_date` in the past |
| Licence expiring | warning | within 7 days |
| No attendance flow | critical | active school with devices but **0 punches in 48h** |
| All devices offline | critical | has devices, none online |
| No devices | warning | active school, 0 devices registered |
| Clock drift | warning | a device clock anomaly today |
| Failed SMS | warning | any failed notification in 48h |
| Sync out-of-sync | info | devices flagged `out_of_sync` |

## Surface

- `GET /api/control-center/health` — the full scan + a rollup
  (`schoolsWithIssues`, counts by severity, counts by type). Control-session
  gated + audited (`viewed_platform_health`).
- `/control/system-health` reworked: the platform banner now says
  *"N schools need attention"* with critical/warning/info chips, above a
  **Schools needing attention** list — each card shows its issues and links to
  `/control/schools/[id]`.

## Code + tests

- `src/lib/control/platform-health.ts` — `getPlatformHealth()` plus the **pure**
  `severityRank` / `worstOf` / `rollup` helpers (8 unit tests). Every monitor
  query is defensive (`.catch → []`) so one missing table never blanks the page.

## Roadmap
