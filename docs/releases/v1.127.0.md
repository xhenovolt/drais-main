# v1.127.0 — Flexible billing: installation fee + installment (pro-rata) payments

**Nature:** minor. Makes the billing model match how DRAIS is actually sold —
a one-time installation fee plus a subscription paid in installments.

Addresses two operator points: plans need an installation fee separate from the
subscription, and schools rarely pay the full amount at once.

## Installation fee (one-time)

Every plan now has an **installation fee** distinct from the recurring
**subscription price**:

- Editable per plan (`/control/plans` → Billing) and shown on the plan card
  (e.g. *"+ UGX 800,000 one-time installation"*).
- Billed **once** — on a school's **first** invoice only. Later invoices
  (renewals) carry the subscription price alone.
- Each invoice records the breakdown (`installation_amount` / `subscription_amount`);
  the Billing panel shows *"#12 · UGX 2,000,000 (incl. UGX 800,000 install)"*.

Presets updated with realistic UGX installation + subscription figures.

## Installment (partial) payments — no longer all-or-nothing

Access is now granted **pro-rata** as money comes in, so a school paying in
installments isn't locked out until the last shilling:

- A payment first covers the **installation fee**; money beyond it buys
  **subscription time proportionally** across the billing period.
- Example: annual sub UGX 1.2M — after installation + UGX 400k (⅓), access
  extends ~⅓ of the year; the balance later extends it further; full payment →
  full period.
- Every payment (partial or full) updates `subscription_end_date`, so the
  existing auto-suspend/dunning all key off real paid-through time.
- The school gets a notice on each part-payment (*"access extended to {date};
  outstanding {amount}"*) and on full payment.

## Code + tests

- `subscriptions.ts` — plan `installation_fee` (additive column, presets, CRUD)
  + **pure** `invoiceAmounts` (3 tests).
- `billing.ts` — invoice `installation_amount` / `subscription_amount`;
  `generateInvoice` bills installation only on the first invoice; `recordPayment`
  now extends access via the **pure** `proratedAccessEnd` (6 tests) on every
  payment; legacy invoices fall back to `amount − installation`.
- 83/83 control tests green.

No new cron; additive schema.
