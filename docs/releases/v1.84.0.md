# DRAIS v1.84.0 — Control Center (Xhenvolt Control Plane v1)

## Release notes

New internal operating console at **/control** — Xhenvolt personnel manage the DRAIS platform without logging into individual schools:

- **First-time setup**: with zero control users, /control offers "Create your first Xhenvolt Super Admin"; afterwards only existing super admins can create operators (Operator / Viewer / Super Admin roles).
- **Dashboard**: schools (total/active/suspended), learners, staff, devices online/offline, SMS usage 24h, clock anomalies today, ranked problem list, platform version.
- **Schools**: every school with status, subscription plan, learners/staff/device counts, last attendance sync and enabled modules; click through to the **operations view** — punches 24h, today's attendance verdicts, per-device online/clock-confidence, sync activity 7d, SMS 48h.
- **Feature management**: per-school module toggles writing the existing `school_modules` registry (super-admin only, audited) — the foundation for feature flags.
- **System health**: DB, SMS, biometric communication, clock integrity, platform version.
- **Audit log**: every Control Center action recorded (who/action/resource/metadata/IP) — viewing a school, toggling a feature, creating an operator, logins.

## Security architecture (isolated by construction)

- **Completely separate auth domain**: new `control_users` / `control_sessions` / `control_audit_logs` tables; scrypt password hashing (unique salt, timing-safe compare); 48-byte session tokens stored only as SHA-256; own `drais_control` cookie (httpOnly, 12h).
- Control code **never imports school auth**; school sessions are neither read nor honored — a school admin/teacher/parent hitting /control APIs gets 401 regardless of their school session.
- School login flow, `users`/`sessions` tables, and middleware behavior for school routes are untouched; /control and /api/control-center were only added to the middleware public list (they enforce their own auth inside).
- APIs live at `/api/control-center/*` to stay clear of the pre-existing JETON `/api/control` channel.

## Database changes

Three additive tables (runtime ensure): `control_users`, `control_sessions`, `control_audit_logs`. No changes to any existing table.

## Testing

- 4 new unit tests (scrypt round-trip/rejects, token hashing, role gate rejecting all school roles incl. `admin`/`super_admin`); 142 total pass.
- Boundary verified: no control file references `getSessionSchoolId`/`drais_session`.
