# v1.107.1 — Suspended devices record no attendance (P2.1)

**Nature:** patch (completes the Suspend semantics shipped in v1.107.0).

## What this closes

v1.107.0 made a platform **Suspend / Retire** durable — the device could no
longer resurrect its own `status` via the heartbeat. But a suspended device that
kept pushing ATTLOG batches would still have its punches turned into attendance.
"Suspend" that keeps recording attendance isn't really suspend.

Now the ZK ingest path gates on the platform status: when a device is
**`suspended`** or **`retired`**, its incoming punches record **no attendance**.

- The raw payload is still persisted (STEP 2, before processing) for the audit
  trail — nothing is hidden.
- The per-record path that writes `zk_attendance_logs` + `attendance_raw_events`
  is skipped, and the skip is logged (`SKIPPED_DEVICE_OUT_OF_SERVICE`).
- The device is still ACK'd normally, so it advances its upload cursor instead of
  retrying the same batch forever.

Re-activating the device (Control Center → Activate) resumes normal recording
immediately.

## Guarding

Two assertions added to `device-isolation.test.mjs` (11 tests total): the ingest
path must gate `suspended`/`retired`, and the heartbeat upsert must not
resurrect a deliberate platform status.

## Roadmap

With this, **Suspend** is fully effective end-to-end. Next up is **P3 — platform
read APIs** (view a school's attendance / devices / health / logs without
impersonation).
