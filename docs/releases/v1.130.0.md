# v1.130.0 — Automation wave Phase 17: predictive health snapshots + founder alerting

**Nature:** minor (E-12 + E-13). Health goes from *pull* (open the console) to
*push* (the platform tells you), with history for trending.

## What this adds

Running daily on the **job runner** (Phase 18 — no new cron):

- **Health snapshots** — every school's health is scored **0–100**
  (critical −40, warning −15, info −5, floored at 0) and stored per day in
  `platform_health_snapshots`, building the trend history the point-in-time scan
  never had.
- **Founder alerting** — when a school **newly turns critical** (vs yesterday's
  snapshot), an alert is raised: recorded in `platform_alerts`, audited, and
  POSTed to **`PLATFORM_ALERT_WEBHOOK`** if configured. Deduped once per school
  per day, and only on a *new* critical (no daily nagging for an already-known one).

## Surfaces

- **System Health → alert feed** at the top: unacknowledged platform alerts
  (linking to the school), each with **Acknowledge**.
- `GET /api/control-center/alerts` (feed + unacked count) · `POST { id }`
  acknowledges.
- `schoolHealthTrend(schoolId, days)` is available for the per-school trend view.

## How it runs (no new cron)

The single existing cron enqueues a daily `platform_health` job (idempotent) that
snapshots + dispatches alerts, with the runner's retry/backoff. Set
`PLATFORM_ALERT_WEBHOOK` (Slack/webhook/email relay) to get alerts off-platform;
without it, alerts still surface in the console feed + audit.
