# v1.124.0 — Money wave Phase 12: payment-gateway webhook reconciliation

**Nature:** minor (E-7). Payments can now reconcile **without a human**.

## What this adds

A provider-agnostic payment webhook so a mobile-money / bank gateway can notify
DRAIS of a payment, and the platform records it, reconciles the invoice, and
auto-reactivates the school — no manual entry.

- **Endpoint:** `POST /api/control-center/billing/webhook`.
- **Auth by signature** — HMAC-SHA256 of the raw body against
  `BILLING_WEBHOOK_SECRET`, sent as `x-billing-signature: sha256=…`. **If the
  secret is unset the endpoint is disabled (503)** — no unauthenticated payment
  can ever be injected.
- **Idempotent** — deduped on the gateway transaction id (`provider_ref`), so a
  retried webhook is a safe no-op (still returns 200 so the gateway stops
  retrying).
- **Reconciles** — reuses the audited ledger `recordPayment`: a full payment
  marks the invoice paid and extends `subscription_end_date`, which lifts
  auto-suspend automatically.

Expected body: `{ invoice_id, amount, provider_ref|transaction_id, method?,
currency?, reference? }` — field aliases are tolerated.

## Wiring a gateway (ops)

1. Set `BILLING_WEBHOOK_SECRET` in the hosting env.
2. Point the provider's webhook at `/api/control-center/billing/webhook`, signing
   the body with that secret.
3. Configure the provider to include the DRAIS **invoice id** (shown on each
   invoice in the Billing panel) in the payment metadata.

## Code + tests

- `src/lib/control/billing-webhook.ts` — **pure** `verifyWebhookSignature`
  (timing-safe, `sha256=` tolerant) + `normalizeWebhookPayload` (5 tests) and
  `recordGatewayPayment` (idempotent, audited `gateway_payment_received`).
- `platform_payments` gains `provider_ref` (additive) for idempotency;
  `recordPayment` accepts a system (null) operator + provider ref.

No new cron.
