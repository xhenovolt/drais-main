# DRAIS v1.94.0 — Identity Correction (operational hardening, Part 2/3/8)

Audit-first response to the biometric/identity hardening brief. Finding: the model is already mature (multi-finger templates, cards, reassign+history, template distribution all exist at the data/service layer — see docs/audits/BIOMETRIC_IDENTITY_HARDENING_AUDIT.md). This release fills the one founder-independence gap that mattered most: correcting a WRONG identity from the attendance context, without ever deleting events.

## What shipped
- **Identity Correction** (Part 2): "PIN FP12345 was mapped to John but belongs to Peter." A **Correct** action on any matched attendance row → search the right person + reason → applied. Under the hood `applyCorrection()`:
  1. reassigns the enrollment via the existing `reassignEnrollment` (history-first),
  2. **re-attributes historical raw events** — events are preserved verbatim (time, device, fingerprint); only the identity label is corrected,
  3. re-evaluates day verdicts for BOTH the old and new person,
  4. records a dedicated `biometric_mapping_history` audit row (who / when / old / new / why / #events).
  Attendance events are immutable; identity associations are correctable and auditable.
- **Create from attendance** (Part 3): the same modal can create a new staff/learner and map the PIN to them inline — the operator never leaves attendance.
- **Auditability** (Part 8): every correction and creation lands in the audited mapping history.

## Already present (documented in the audit, not rebuilt)
- Part 4 multi-finger: `biometric_templates(enrollment_id, finger_index, …)` — 1:many per person.
- Part 5 cards: `biometric_enrollments.card_number`, handled in enrollment-service.
- Part 6 template sync: `template-service.queueDistributionsForSchool()` distributes to devices.
- Part 7 model separation: person ← enrollments (pin/card) ← templates; events reference person; devices standalone.
