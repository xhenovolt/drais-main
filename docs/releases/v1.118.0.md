# v1.118.0 — Plan billing model (price / cycle / installments / deliverables) + renewal

**Nature:** minor (plans become commercial products, enabling renewal + billing-
driven auto-suspend). Also fixes a light-theme navbar legibility bug.

## Why

Plans defined *entitlements* (limits + modules) but not *commercial terms* — so
there was nothing to drive renewal or auto-suspend. Now every plan carries:

- **price** + **currency** (default UGX),
- **billing cycle** — `monthly` / `termly` / `annual` / `one_time`,
- **installments** — split the price into N payments (with the per-installment
  amount shown),
- **deliverables** — the explicit list of what the school gets.

## The auto-suspend / renewal loop (now closed)

- **Assigning** a plan sets `subscription_end_date = today + cycle` and marks the
  school active. A `one_time` plan sets no expiry.
- The **session gate already auto-suspends** a school once that date passes
  (added in the schools-lifecycle work) — so billing lapse → access blocked,
  automatically.
- **Renew** (new action + button on the school's Plan panel) extends by one more
  cycle from the later of *today* or the current end date (early renewals stack)
  and clears the lapsed state.

Plan assignment and renewal are audited (`plan_assigned` with price/cycle/end,
`subscription_renewed`).

## Surfaces

- `/control/plans` editor: price, currency, installments, billing-cycle selector,
  and an add/remove **deliverables** list. Cards show the price, cycle, per-
  installment amount, and a ✓ deliverables list.
- School Plan panel: plan price/cycle line + a **Renew** button.
- `POST /api/control-center/schools/[id]` gains a `renew` action; the plans API
  persists the billing fields.
- Presets seeded with sensible UGX pricing (Starter … Government).

## Code + tests

- `control/subscriptions.ts` — billing columns (additive migration) + pure
  `billingCycleDays` / `nextEndDate` / `installmentAmount` (9 subscription tests)
  + `renewSchool`.

## Bug fix — light-theme navbar

The "DRAIS CONTROL CENTER" wordmark (and any text with no explicit colour class)
*inherited* the dark theme's light default, so it stayed light-on-white. The
light theme now sets the base text colour on the root, not just the background.
