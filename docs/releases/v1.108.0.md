# v1.108.0 — Platform read: see a school operating without impersonation (Roadmap P3)

**Nature:** minor (completes the platform read surface).

## What this closes

Defect #4 / founder-dependence **F-4**: to check a specific school's live
operations, an operator had to *impersonate* it. Impersonation should be a
troubleshooting tool, not the way you read a school.

The `/control/schools/[id]` operations view already surfaced a lot directly
(attendance-today counts, devices, device time-confidence, SMS, 7-day sync). This
release adds the one thing that still required logging in as the school:

### Recent activity (live)

A read-only panel showing the school's **last 15 punches** — resolved name where
matched (or the unmatched device PIN), role, device SN, and time — computed
straight from `attendance_raw_events` with the platform (control) session. An
operator can now confirm at a glance that attendance is flowing, from the
Control Center, **without impersonating the tenant**.

Every school view is still audited (`viewed_school` in `control_audit_logs`).

## What the platform read now covers (no impersonation needed)

| Signal | Source |
|---|---|
| Attendance today (staff/learners present·late·absent) | `attendance_records` |
| Punches (24h) | `attendance_raw_events` |
| **Recent activity (live punches, named)** | **new this release** |
| Devices + online state | `devices` |
| Device time confidence | `device_clock_health` |
| SMS (48h) | `notification_outbox` |
| Sync activity (7d) | `attendance_raw_events` |

Impersonation ("Open school") remains available on the same page as an explicit
**troubleshooting** action — not the default path to read a school.

## Code

- `GET /api/control-center/schools/[id]` gains `recent_punches` (last 15, name
  resolved via `people`, school-scoped).
- `/control/schools/[id]` gains a **Recent activity (live)** panel.
