# v1.131.0 — Resilience Phase 22: per-tenant data export (operator-controlled backup)

**Nature:** minor (E-19). A real, operator-controlled DR capability on top of
TiDB Cloud's cluster snapshots.

## What this adds

TiDB Cloud already takes automated cluster backups — but those aren't something
you can hold, inspect, or hand to a school. This adds a **per-tenant export**:

- **Export data** on a school's operations view (super-admin) → downloads that
  school's **entire dataset** — every row across every `school_id`-scoped table —
  as a single JSON file (`drais-export-<school>-<date>.json`).
- It's the portable **backup / DR extract / data-portability** artefact, and the
  natural **export-before-hard-delete** safeguard.

Bounded (≤100k rows/table, over-limit tables flagged as `truncated`), audited
(`school_data_exported` with table + row counts), and super-admin only.

## DR posture (documented)

- **Cluster backups:** TiDB Cloud automated snapshots (point-in-time) — the
  primary restore path, owned at the database tier.
- **Per-tenant portability:** this export — pull any single school's data on
  demand, independent of the cluster.
- **Restore runbook:** for a full restore, restore the TiDB snapshot from the
  cloud console; for a single school, re-import from its JSON export.

## Code

- `src/lib/control/data-export.ts` — `exportSchoolData(schoolId)` (discovers
  school-scoped tables via `INFORMATION_SCHEMA`, validated identifiers, bounded).
- `GET /api/control-center/schools/[id]/export` — streams the JSON download.
- **Export data** button in the school Lifecycle panel.

No new cron; no schema change.
