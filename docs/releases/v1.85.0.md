# DRAIS v1.85.0 — Attendance Intelligence Engine (per-record confidence)

## Attendance Intelligence Program · Phase 3

Every attendance punch now carries its own trust score instead of being assumed correct.

## Release notes
- Five sub-confidences + one overall per record: **identity** (match state, matcher score, provisional), **time** (time source, skew, day clock-health, corrections), **device** (known/online), **policy** (rule/shift resolved vs raw fallback), **overall** (weighted, identity+time gated so a wrong-person or wrong-clock punch can never read as trusted).
- **Confidence chip on every attendance/logs row** (desktop + mobile): green/amber/red with the percentage; hover reveals all five sub-scores and the reason each was lowered.
- Reason strings are plain-language ("Unmatched — no confirmed person", "Device clock flagged as drifting for this day", "Provisional identity — auto-linked, not yet confirmed").

## Architecture
- `src/lib/attendance/confidence-scoring.ts` — **pure** `scoreRecord()` (16 unit tests, no DB/clock). Consumes evidence the pipeline already records (Digital Twin fields, Time Intelligence clock health, engine verdicts); the history API composes it per row. Nothing new is written.

## Database changes
None — the history query joins existing `device_clock_health` and `attendance_records`; no schema changes.

## Validation
Live on JIPRA: matched staff score 94% high; the unmatched punch scores 35% low (identity 10).
