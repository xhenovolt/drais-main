# Issue 2 — Route-specific developer documentation (result)

Baseline: `2026-10-directive-baseline.md` § Issue 2. Labels as there.

## Reconnaissance (what existed)
- **VERIFIED** — `/control/docs`: ~45 hand-written topic pages (`registry.ts` drives nav and search; `ControlDoc.tsx` renders), gated by the Control Center layout and the `docs.view` permission. Organised by topic and module. No per-route or per-file page, no generator, no staleness check. Search matched only titles, topics and keywords.
- Kept and extended rather than replaced: the new pages use the same shell, registry and primitives.

## What was built
- **Generator** `scripts/devdocs/analyze.mjs` + `generate.mjs`. Parses all ~2,100 source files with the TypeScript compiler (syntax only). It records, per file:
  - directive, header comment (verbatim) and top-level declarations with line ranges and JSDoc;
  - imports (resolved; broken or case-mismatched flagged), dependants and dynamic imports;
  - hooks by source, plus `useState`/`useReducer` state with setters;
  - JSX components rendered, forms and className count, i18n usage;
  - requests (`fetch`/`apiFetch`/`useSWR`/axios/`EventSource`). URLs are followed through templates, conditionals, `+`, local variables and constants imported from other modules, then matched to the actual `route.ts` and its exported methods;
  - for API routes: HTTP methods, SQL tables (filtered against tables the repo actually creates), session/permission/delegated-auth calls, retired stubs, route config;
  - tests that import a file, and related tests through its imports.

  Per route, it records the real layout / loading / error-boundary chain (route groups and `_private` folders handled), sidebar label and middleware public status. Each documentation section gets a completeness state: from code, none found, inherited, related tests only, or needs manual review.
- The index (~7 MB) is git-ignored and regenerated by `prebuild` / `prebuild:electron`, so it cannot lag the code. `npm run docs:gen` regenerates locally.
- **API** `/api/control-center/docs/{tree,route,file,search}` with `requireControl(req, 'docs.view')`. The index is read with `fs` on the server and cached per process; only one route, one file, or 60 search results are sent to the browser. It is included in deployments via `outputFileTracingIncludes`.
- **UI** `/control/docs/routes/<url>`, `/control/docs/files/<path>` and the reference home:
  - real route tree (pages / API) with a filter, and breadcrumbs;
  - per-route sections: guide, purpose, architecture, APIs called, data flow, components, hooks & state, code blocks, imports, auth, styling, tests, called-by;
  - "Used by" with a warning above 10 dependants;
  - GitHub source links at the generating commit;
  - search: partial, case-insensitive, category filters with counts, highlighting, empty state, and a *Problems* category;
  - coverage table and six common-task shortcuts on the home page.
- **Hand-written depth**:
  - `/attendance/settings` teaching example: layers, server vs client, data flow, tabs, validation, loading/errors, recorded gaps, a "where does new code go" table, and JS/PHP analogies labelled as analogies.
  - `/attendance` data loading.
  - Root layout, and `(protected)/layout.tsx` — verified to wrap no page.
  - Pointer from `/students/list` to its blueprint.
  - New docs: *Add a custom tab* (playbook) and *Conventions to avoid* (11 entries, each with a real instance).
- **Staleness tests** `npm run test:devdocs` (16) cover:
  - the analyser on a fixture tree;
  - every served `page`/`route` file being documented and every file parsing;
  - known facts of real routes;
  - every guide target existing and having a body;
  - every `<Source>`/file link in all docs resolving;
  - search relevance.
