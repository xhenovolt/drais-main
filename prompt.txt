PHASE 4D — CHECK-IN / CHECKOUT ALGORITHM
========================================

Implement deterministic daily classification.

Do not trust the device blindly.

ZKTeco may send punch state, but many deployments do not configure in/out mode correctly.

DRAIS must support two modes:

MODE 1 — DEVICE_MODE_TRUSTED

Use device io_mode/punch_state if the school explicitly enables it.

MODE 2 — SMART_TIME_MODE

Default mode.

Classify based on time windows and daily state.

SMART_TIME_MODE logic:

For each person per school day:

1. First valid punch of the day before checkout_start should be CHECK_IN.

2. First valid punch within arrival window should be ON_TIME_CHECK_IN.

3. First valid punch after arrival_end but before absence_cutoff should be LATE_CHECK_IN.

4. First valid punch after absence_cutoff but before checkout_start should be VERY_LATE_OR_MANUAL_REVIEW depending on school policy.

5. Punch inside departure window should be CHECK_OUT.

6. Punch before departure_start after a valid check-in should be EARLY_LEAVE unless within duplicate window.

7. Punch after expected work/school end should be CHECK_OUT or OVERTIME_CHECKOUT depending on role and rule.

8. Multiple punches within duplicate window should be DUPLICATE_IGNORED.

9. If only one punch exists for the day:

   * before checkout_start: treat as check-in
   * inside checkout window with no check-in: mark AMBIGUOUS_SINGLE_PUNCH or CHECKOUT_WITHOUT_CHECKIN depending on policy
   * after checkout window: mark AMBIGUOUS_LATE_PUNCH or OVERTIME_WITHOUT_CHECKIN depending on policy

10. Do not overwrite first_checkin when later punches arrive.

11. Update last_checkout only when punch qualifies as checkout/departure.

12. Keep all raw punches for audit.
